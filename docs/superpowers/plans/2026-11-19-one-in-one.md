# One-In-One (1일 1학습) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 깃허브로 로그인해 유형별 하루 한 문제(최대 4문제)를 풀면, 자동 채점 후 사용자의 `One-In-One` 저장소에 커밋되고, 사용자끼리 꾸준성·도전 문제 수·커밋 수로 비교하는 모바일 우선 웹앱.

**Architecture:** Next.js App Router 한 프로젝트가 화면과 API를 모두 담당하고 Vercel에 배포한다. 비즈니스 규칙(날짜, 출제, 채점, 집계)은 `src/lib/` 아래의 순수 함수로 두고 단위 테스트한다. DB(Supabase Postgres)와 GitHub 호출은 얇은 어댑터 뒤에 두고, 서비스 계층은 어댑터 인터페이스에만 의존해 가짜 구현으로 테스트한다. 문제 은행은 저장소의 JSON 파일이며 서버에서만 읽는다.

**Tech Stack:** Next.js 15 (App Router, TypeScript), React 19, Tailwind CSS 4, next-auth v5 (GitHub provider), @supabase/supabase-js 2 (서버 전용, service role), @octokit/rest 21, Pyodide 0.26.x (jsDelivr CDN, Web Worker), CodeMirror 6 (`@uiw/react-codemirror` + `@codemirror/lang-python`), Vitest 2, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-daily-study-design.md`

## Global Constraints

- 날짜 경계는 한국 시간(Asia/Seoul) 자정. 날짜 문자열은 `YYYY-MM-DD`. 주는 월요일 시작.
- 문제 유형 키와 표시명: `ai`=AI, `network`=네트워크, `claude-code`=Claude Code, `coding-test`=코딩 테스트. 탭 순서도 이 순서.
- 저장소 기본 이름 `One-In-One`, 충돌 시 입력 기본값 `One-In-One-2`. 앱 표식 파일은 저장소 루트의 `.one-in-one`.
- 저장소 경로: `<YYYY-MM-DD>/<type>/<correct|wrong>/problem.md` 와 `answer.md`. 같은 경로는 덮어쓴다.
- GitHub OAuth 앱, 요청 scope는 `read:user public_repo`. 로그인 화면 문구: "앱은 One-In-One 저장소에만 씁니다".
- 코딩 테스트 언어는 Python만. 코드는 브라우저(Pyodide)에서만 실행한다. 서버는 사용자 코드를 실행하지 않는다.
- 객관식 정답(`answerIndex`)과 해설은 제출 응답에도 담지 않는다. 사용자가 "해설 보기" 버튼을 누를 때만 `GET /api/explanation`으로 받는다. 이 API는 오늘 그 문제에 저장된 시도가 1개 이상일 때만 응답한다(아니면 403). 해설을 본 뒤에도 다시 풀기는 허용.
- 커밋되는 `answer.md`의 `## 해설`은 정답 커밋에만 넣는다.
- 유료 API 호출 없음 (AI 채점 없음).
- 모든 수치(연속 일수, 출석률, 잔디, 랭킹)는 `commit_status = 'committed'`인 시도만 센다. 날짜는 시도의 제출 날짜(`date_kst`).
- 오답만 있는 날도 도전한 날이다.
- 커밋 수: 정답 커밋은 모두, 오답 커밋은 같은 (날짜, 문제)당 최대 4개까지 센다.
- 빈 제출(보기 미선택, 공백·주석뿐인 코드, 시작 코드와 공백 무시 동일)은 서버에서 400으로 거부하고 아무것도 기록하지 않는다. 안내 문구: "코드를 작성해 주세요".
- 유형을 맞히면 그날 그 유형은 완료 — 이후 제출은 409.
- 버튼 문구: "제출하고 커밋하기", "테스트 실행", "다시 풀기", "저장소 다시 연결하기", 설정 "랭킹에 나를 숨기기".
- UI: 강조색 `#1A7F37`, 본문 `#1F2328`, 보조 `#59636E`, 테두리 `#D0D7DE`, 오답 `#BC4C00`, 서체 Noto Sans KR. 터치 영역 최소 44px. 시안: https://claude.ai/artifact/LjbQZTVcKvpUPrsBB9eLgw (홈=B, 문제=A, 코딩 화면=C 참고).
- 하단 메뉴: 홈 / 랭킹 / 내 정보.

## Review Focus

1. **자정 직전·직후 제출:** 23:59에 불러온 문제를 00:01에 제출하면, 서버가 오늘(KST) 문제와 다르므로 409 `{error:"date_changed"}`를 돌려주고 화면은 새 문제를 다시 불러온다. → Task 7 테스트.
2. **커밋이 다음 날 재시도로 성공:** 제출일(`date_kst`)로 집계되고 연속 일수가 끊기지 않는다. → Task 4·7 테스트.
3. **제출 버튼 연타·동시 제출:** 같은 유형을 이미 맞혔으면 두 번째 정답은 409. DB에 (user, date, type) 정답 유일 인덱스. → Task 5·7 테스트.
4. **토큰 회수·저장소 삭제:** 커밋이 401/403/404면 재시도를 멈추고 `repo_status='disconnected'`, 홈 상단에 "저장소 다시 연결하기". 다른 오류는 `pending` 유지. → Task 6·7 테스트.
5. **검토된 문제가 0개인 유형:** 그 유형 탭은 "준비 중"을 보여 주고 제출 API는 404. 앱은 깨지지 않는다. → Task 2 테스트.

### Task 4: 집계와 랭킹

**Files:**
- Create: `src/lib/stats/stats.ts`, `src/lib/stats/ranking.ts`
- Test: `tests/lib/stats.test.ts`, `tests/lib/ranking.test.ts`

**Interfaces:**
- Consumes: `addDays`, `weekStartKst`, `WRONG_COMMIT_CAP`
- Produces:
  - `type CountedAttempt = { dateKst: string; problemId: string; type: ProblemType; isCorrect: boolean }` (호출 측이 committed만 넘긴다)
  - `activeDays(a: CountedAttempt[]): Set<string>`
  - `currentStreak(days: Set<string>, today: string): number` — 오늘이 있으면 오늘부터, 없으면 어제부터 거꾸로 센다.
  - `attendance30(days: Set<string>, today: string): number` — `[today-29, today]` 안의 날 수 / 30, 0~1.
  - `weeklyStreak(days: Set<string>, today: string): number` — `currentStreak`와 같은 시작점, 단 `weekStartKst(today)` 이전 날짜는 세지 않음.
  - `distinctProblems(a: CountedAttempt[]): number` — 서로 다른 `problemId` 수.
  - `countedCommits(a: CountedAttempt[]): number` — 정답 전부 + (dateKst, problemId)별 오답 `min(n, 4)`.
  - `inWeek(a: CountedAttempt[], today: string): CountedAttempt[]` — `weekStartKst(today) ≤ dateKst ≤ today`.
  - `heatmap(days: Set<string>, today: string, weeks = 12): { date: string; active: boolean }[]` — 오늘이 포함된 주까지 `weeks*7`칸, 월요일 시작 열 순서.
  - `ranking.ts`: `type Metric = 'consistency'|'problems'|'commits'`; `type Period = 'week'|'all'`; `type RankUser = { userId: string; login: string; avatarUrl: string; repoName: string; hidden: boolean; attempts: CountedAttempt[] }`; `type RankRow = { rank: number; userId: string; login: string; avatarUrl: string; repoUrl: string; primary: number; secondary: number | null }`; `rankUsers(users: RankUser[], metric: Metric, period: Period, today: string): { rows: RankRow[]; me: (userId: string) => RankRow | null }`.
  - 정렬 규칙: consistency/all → (currentStreak desc, attendance30 desc), primary=streak, secondary=출석률 % 정수; consistency/week → (weeklyStreak desc, currentStreak desc), secondary=null; problems → distinctProblems desc; commits → countedCommits desc. week면 problems/commits에 `inWeek` 적용. 동점은 같은 순위(1,1,3), 동점 내 표시 순서는 login 오름차순. hidden 사용자는 `rows`에서 빠지지만 `me()`는 숨김 사용자에게 `null`. 0점 사용자도 포함.

- [ ] **Step 1: 실패하는 테스트 작성** (`today = '2026-11-19'`, 목요일)

```ts

expect(currentStreak(d('2026-11-17','2026-11-18','2026-11-19'), today)).toBe(3);
expect(currentStreak(d('2026-11-17','2026-11-18'), today)).toBe(2); // 오늘 미완료 → 어제까지
expect(currentStreak(d('2026-11-16','2026-11-18'), today)).toBe(1);
expect(currentStreak(d(), today)).toBe(0);
expect(weeklyStreak(d('2026-11-14','2026-11-15','2026-11-16','2026-11-17','2026-11-18','2026-11-19'), today)).toBe(4); // 월~목만
expect(weeklyStreak(d('2026-11-15'), '2026-11-16')).toBe(0); // 월요일, 오늘 미완료, 어제는 지난주
expect(attendance30(d('2026-10-20','2026-10-21','2026-11-19'), today)).toBeCloseTo(2/30); // 10-20은 범위 밖
const wrong = (n: number) => Array.from({length:n}, () => ({dateKst:today, problemId:'network-001', type:'network' as const, isCorrect:false}));
expect(countedCommits([...wrong(6), {dateKst:today, problemId:'network-001', type:'network', isCorrect:true}])).toBe(5);
```

    ```ts
    type SubmitResult =
      | { ok: true; isCorrect: boolean; commit: { status: 'committed'; url: string } | { status: 'pending' } }
      | { ok: false; status: 400; error: 'empty' } | { ok: false; status: 404; error: 'no_problem' }
    ```

    순서: 사용자 `repoStatus!=='ok'` → 412 → 오늘(KST) 문제 없음 → 404 → `problemId` 불일치 → 409 date_changed → 빈 제출 → 400 → 오늘 그 유형 정답 존재 → 409 already_solved → 채점(코딩은 `input.passed`) → `insertAttempt` (`DuplicateCorrectError` → 409 already_solved) → 커밋 시도: 성공 시 `markCommitted`, `url = https://github.com/<login>/<repo>/commit/<sha>`; `RepoAccessError`면 `repoStatus='disconnected'`로 바꾸고 pending; 그 외 오류는 pending. 응답에는 해설과 `answerIndex`를 담지 않는다.

  - `retryPending(deps, userId: string): Promise<{ committed: number; stopped: boolean }>` — `repoStatus!=='ok'`면 아무것도 안 함. pending을 오래된 순으로 커밋. `RepoAccessError`면 disconnected로 바꾸고 중단(`stopped:true`). 다른 오류는 그 시도를 남기고 다음으로.
