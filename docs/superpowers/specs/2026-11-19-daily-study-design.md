## 1. 의도와 이유

IT 취업 준비생, 그리고 Claude Code 같은 개발 도구를 처음 접하는 사람들이 **하루에 한 문제씩** 풀고, 그 기록이 **본인 깃허브 저장소에 매일 커밋**되도록 하는 웹앱이다. **[결정]**

- 매일 조금씩 공부하는 습관을 만든다.
- 공부한 흔적이 깃허브 잔디와 저장소로 남아, 그 자체가 포트폴리오/공부 노트가 된다.
- 다른 사용자와 꾸준함을 비교하면서 동기부여를 얻는다. **[결정]**

## 2. 목표 / 비목표 / 반목표

**목표**
- 깃허브 로그인 한 번이면 바로 문제를 풀 수 있다. git을 몰라도 된다. **[결정: 앱이 대신 커밋]**
- 하루에 유형별로 한 문제씩, 1~4문제를 원하는 만큼 푼다. **[결정]**
- 제출하면 자동 채점되고, 결과가 사용자 저장소에 커밋된다. **[결정]**
- 사용자끼리 꾸준성·도전 문제 수·커밋 수로 비교하는 랭킹이 있다. **[결정]**
- 모바일에서 쓰기 편하다(사용자가 주로 모바일). **[결정]**

**비목표 (첫 버전에 안 함)**
- AI가 서술형 답을 채점하거나 피드백하는 기능 (비용 때문에 제외). **[결정]** 나중에 선택 기능으로 붙일 수 있게만 둔다.
- 앱스토어용 네이티브 앱. 모바일 웹 + 홈 화면 추가(PWA)로 대신한다. **[제안]**
- Python 외 코딩 언어. **[제안]**
- 웹에서 문제를 추가·수정하는 관리자 화면. **[제안]**

**반목표 (이렇게 되면 기술적으로 돌아가도 실패)**
- 틀렸다는 이유로 기록이 끊겨 의욕이 꺾이는 것. 틀려도 시도는 기록된다. **[제안]**
- 비교가 부담스러운 사용자가 원치 않게 랭킹에 노출되는 것. **[제안]**
- 운영 비용이 사용자 수에 비례해 커지는 구조 (유료 API 호출 등). **[결정: 비용 때문에 AI 채점 제외]**

## 3. 제약

- 운영 비용은 무료 요금제 안에서 시작한다(Vercel, Supabase 무료 플랜). **[제안]**
- 사용자의 깃허브 계정에 쓰기 권한이 필요하다. 권한 범위는 가능한 한 좁게 잡는다.
- 날짜 기준은 한국 시간(Asia/Seoul) 자정이다. **[제안]** 대상이 한국 취업 준비생이므로.

## 5. 결정된 설계

### 5.1 기술 스택 **[제안]**
- **Next.js (App Router, TypeScript)** — 화면과 서버 API를 한 프로젝트로. **Vercel** 배포.
- **Supabase (Postgres)** — 사용자·풀이 기록·랭킹 집계.
- **깃허브 로그인** — **GitHub OAuth 앱, `public_repo` 권한** **[결정]**. 로그인 한 번으로 시작하고 앱이 저장소를 자동으로 만든다. 이 권한은 사용자의 모든 공개 저장소에 쓸 수 있으므로, 로그인 화면에 "앱은 `One-In-One` 저장소에만 씁니다"라고 쉬운 말로 안내한다. 좁은 권한(GitHub 앱)은 시작 단계가 늘어나서 택하지 않았다. 로그인 세션 관리 방식은 [빌더 재량] (Auth.js 또는 Supabase Auth).
- **깃허브 커밋** — 서버에서 사용자 토큰으로 GitHub REST API 호출.
- **코딩 테스트 실행** — 브라우저에서 Pyodide로 Python 실행·채점. 서버에서 사용자 코드를 돌리지 않는다.
- 모바일 우선 반응형 + PWA(홈 화면 추가).

### 5.2 문제 유형 **[결정]**
네 가지 탭: **AI · 네트워크 · Claude Code · 코딩 테스트**

| 유형 | 형식 | 채점 |
|---|---|---|
| AI | 객관식 4지선다 + 해설 | 서버에서 정답 비교 |
| 네트워크 (컴퓨터네트워크 기본 개념) | 객관식 4지선다 + 해설 | 서버에서 정답 비교 |
| Claude Code (개념) | 객관식 4지선다 + 해설 | 서버에서 정답 비교 |
| 코딩 테스트 (쉬운 난이도) | Python 함수 작성 | 브라우저에서 테스트 케이스 실행 |

- 객관식의 정답은 제출 전 브라우저로 보내지 않는다(서버에서 채점). **[제안]**
- 코딩 테스트는 브라우저에서 채점하므로 조작 가능성이 있다. 랭킹 기준이 "정답 수"가 아니라 "꾸준성·도전 수·커밋 수"라서 영향이 작다고 보고 감수한다. **[제안]**

### 5.3 오늘의 문제 **[제안]**
- 유형마다 하루 한 문제. **모든 사용자가 같은 날 같은 문제**를 받는다.
- 사용자는 그날 1~4개 유형을 골라서 푼다. **[결정]**
- 문제 은행: **유형별 7문제(총 28문제, 1주일 분량)를 Claude가 초안으로 만들고, 사용자가 검토한 뒤 출시한다. 나머지는 운영하면서 채운다.** **[결정]** 첫 버전의 개발 범위에 이 28문제 작성이 포함된다. 목표는 유형별 30문제.
- 검토가 끝난 문제만 출제된다(문제 파일에 검토 완료 표시). **[Claude 결정]**
- 문제는 앱 저장소 안에 파일(JSON 또는 Markdown)로 두고 버전 관리한다. DB에 넣을지 파일로 둘지는 [빌더 재량]이지만, 정답이 브라우저로 새지 않아야 한다.
- 문제를 다 쓰면 처음부터 다시 돈다(순환). 문제 추가는 파일을 추가하는 방식.

### 5.4 풀이와 제출 흐름
1. 깃허브 로그인. 첫 로그인 시 사용자 계정에 **공개 저장소 `One-In-One`**를 만든다. **[제안]**
   - 같은 이름의 저장소가 이미 있으면 덮어쓰지 않는다. 그 저장소가 앱이 만든 것(루트에 앱 표식 파일이 있음)이면 그대로 쓰고, 아니면 첫 화면에서 다른 이름을 입력받는다(기본값 `One-In-One-2`). **[Claude 결정]**
   - 저장소가 삭제되거나 권한이 회수되면 커밋 재시도를 멈추고, 앱 상단에 "저장소 다시 연결하기" 안내를 띄운다. 그동안의 시도는 DB에 남는다. **[Claude 결정]**
2. 홈(B)에서 유형을 고르면 문제 화면(A, 상단 탭)으로 이동.
3. 답을 고르거나 코드를 쓰고 **"제출하고 커밋하기"**.
4. 채점 결과(정답/오답)를 보여 주고, 저장소에 커밋한다. **해설과 정답은 사용자가 "해설 보기" 버튼을 누르기 전까지 보여 주지 않는다.** **[결정]** 버튼은 그 문제에 한 번 이상 제출한 뒤에만 나타난다. 해설을 본 뒤에도 다시 풀기는 막지 않는다. **[Claude 결정]**
5. **오답이면 다시 풀 수 있다.** 시도할 때마다 커밋한다. **[제안]**
6. 한 유형을 **맞히면 그 유형은 그날 완료**. 더 제출할 수 없다. **[제안]**

### 5.5 저장소 폴더 구조 **[결정: 날짜 → 유형 → 정답/오답 → 문제·답안 순서]**
```
One-In-One/
  2026-11-19/
    network/
      wrong/
        problem.md   ← 문제 내용 (보기 포함)
        answer.md    ← 내가 쓴 답안 (해설은 correct/ 쪽에만 넣는다 — 오답 커밋으로 정답이 새지 않게) [Claude 결정]
      correct/
        problem.md
        answer.md
    claude-code/
      correct/
        problem.md
        answer.md
    coding-test/
      correct/
        problem.md
        answer.md    ← 제출 코드 (언어 표기된 코드 블록) + 테스트 결과
```
- 폴더명은 영어(`ai`, `network`, `claude-code`, `coding-test`, `correct`, `wrong`). 한글 경로는 깃허브 URL에서 깨져 보이고 다루기 번거로워서. **[제안]**
- 오답 후 다시 맞히면 `wrong/`과 `correct/`가 둘 다 남는다. **[제안]**
- 같은 유형을 여러 번 틀리면 `wrong/` 안의 파일은 마지막 시도로 덮어쓴다. 이전 시도는 git 이력에 남는다. **[제안]**
- 커밋 메시지 형식 예: `2026-11-19 network: wrong` **[빌더 재량]**
- 커밋 작성자는 사용자 본인 토큰으로 생성되어 사용자 깃허브 잔디에 반영된다.

### 5.6 랭킹 **[결정: 꾸준성 · 도전 문제 수 · 커밋 수]**
| 기준 | 정의 |
|---|---|
| 꾸준성 | 현재 연속 일수 + 최근 30일 출석률(문제를 하나라도 푼 날 / 30). 정렬은 연속 일수 우선, 동률이면 출석률. **[제안]** |
| 도전 문제 수 | 시도한 서로 다른 문제 수(정답·오답 무관, 같은 문제 재도전은 1개). |
| 커밋 수 | 앱이 사용자 저장소에 성공적으로 남긴 커밋 수(재도전 포함). 단 **오답 커밋은 한 문제당 4번까지만 센다.** **[결정]** 5번째 오답부터도 다시 풀기와 커밋은 그대로 되지만 커밋 수에는 더해지지 않는다. 정답 커밋은 항상 센다. 따라서 한 문제에서 셀 수 있는 커밋은 최대 5개(오답 4 + 정답 1). **[Claude 결정]** |

- 기간 탭: **이번 주(월요일 시작, 한국 시간)** / **전체**. **[제안]**
  - "이번 주" 탭의 꾸준성은 **이번 주 안에서 연속으로 문제에 도전한 날 수(0~7일)**다. "도전한 날"은 **커밋이 1번 이상 성공한 날**이다. **[결정]** 오늘 아직 안 했으면 어제까지 이어진 연속으로 본다. 도전 문제 수·커밋 수는 이번 주 것만 센다. **[Claude 결정]**
- **모든 날짜 기준은 커밋 기준으로 통일한다.** "도전한 날" = 커밋이 1번 이상 성공한 날. 이번 주·전체 랭킹의 연속 일수와 출석률, 홈 화면의 연속 일수와 잔디 모두 같은 기준이다. **[결정]** 커밋 실패는 자동 재시도하며, 재시도가 성공하면 원래 제출한 날짜로 센다. **[Claude 결정]**
- **오답만 있는 날도 "도전한 날"로 센다.** 반목표("틀렸다고 기록이 끊기지 않게")에 따른 것. **[Claude 결정]**
- **빈 제출은 받지 않고 어떤 수치에도 세지 않는다.** **[결정]** 기준은 다음과 같다. **[Claude 결정]**
  - 객관식: 보기를 고르지 않으면 제출 버튼이 비활성화된다.
  - 코딩 테스트: 코드가 비어 있거나, 공백·주석만 있거나, 처음 주어진 시작 코드와 (공백 무시하고) 똑같으면 제출을 막고 "코드를 작성해 주세요"라고 안내한다.
  - 같은 검사를 서버에서도 한 번 더 한다. 걸리면 DB 기록도 커밋도 남기지 않는다.
- 각 행: 순위, 깃허브 프로필 사진, 아이디, 수치. 누르면 그 사용자의 `One-In-One` 저장소로 이동. **[제안]**
- 내 순위는 목록 아래에 고정 표시. **[제안]**
- 설정의 **"랭킹에 나를 숨기기"**를 켜면 랭킹 목록에 나타나지 않는다. **[제안]**
- "연속 일수"는 오늘 아직 안 풀었으면 어제까지의 연속으로 본다(자정 전까지 끊기지 않음). **[제안]**

### 5.7 화면 **[결정: B + A 조합]**
하단 메뉴: **홈 / 랭킹 / 내 정보** **[제안]**

- **홈 (시안 B):** 연속 일수 배지, 최근 12주 잔디, 오늘 진행률(n/4), 유형별 행(정답/오답/안 풂 배지). 행을 누르면 문제 화면.
- **문제 (시안 A):** 상단에 4개 유형 탭(완료한 탭은 체크), 문제·보기, 하단 고정 "제출하고 커밋하기" 버튼. 코딩 테스트는 코드 편집기 + "테스트 실행" 버튼(시안 C의 코딩 화면 참고).
- **결과:** 제출 후 같은 화면에서 정답/오답, 커밋 링크, **"해설 보기" 버튼**을 보여 주고 오답이면 "다시 풀기". 해설은 버튼을 눌러야 펼쳐진다. **[결정]**
- **랭킹:** 기간 탭, 기준 탭, 목록, 하단 내 순위.
- **내 정보:** 내 저장소 링크, 랭킹 숨기기 설정, 로그아웃.
- 색·서체는 시안을 따른다(깃허브 초록 계열 강조색, Noto Sans KR). 세부는 [빌더 재량].

### 5.8 데이터 (개략) **[제안]**
- `users`: 깃허브 id, 아이디, 프로필 사진, 저장소 이름, 랭킹 숨김 여부, 가입일.
- `attempts`: 사용자, 날짜(KST), 유형, 문제 id, 정답 여부, 제출 내용, 커밋 SHA(성공 시), 생성 시각.
- 랭킹 수치는 `attempts`에서 집계(뷰 또는 주기적 집계). 방식은 [빌더 재량].
- 커밋이 실패하면 시도는 DB에 남기고 커밋은 재시도 대상으로 표시한다. **랭킹·연속 일수·잔디 등 모든 수치는 커밋이 성공한 시도만 센다.** **[결정]**
